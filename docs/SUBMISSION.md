# Kassa Sentinel — материалы для сдачи (раздел 8 ТЗ)

Локальный AI-сервис для проверяющего: по записи потолочной камеры кассы показывает эпизоды с признаками
возможных нарушений — тип, таймкод, 1–3 кадра-доказательства, описание того, что видно, и ссылку на норму РК.
Результат — подсказка для проверки человеком, не юридическое заключение.

## 1. Адреса и доступ

| Что | Значение |
|---|---|
| Веб-интерфейс | https://bachelor-msgstr-expenses-pixel.trycloudflare.com/ — вход по API-ключу |
| API для жюри | `POST https://bachelor-msgstr-expenses-pixel.trycloudflare.com/api/v1/analyze`, `GET https://bachelor-msgstr-expenses-pixel.trycloudflare.com/api/v1/jobs/{job_id}` |
| Ключ | передаётся отдельно; заголовок `X-API-Key`; без верного ключа — 401 |

Публичный адрес — Cloudflare Tunnel к серверу команды (ноутбук с RTX 4060). Пример запроса — ровно как в ТЗ:

```bash
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
curl https://<адрес>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ответ `GET` до готовности — `{"job_id", "status": "processing", "stage", "progress"}`, после — схема ТЗ
(`verdict`, `violations[type, timecode_sec, description, evidence_frames[timestamp_sec, image_base64]]`).
Дополнительно внутри нарушения: `type_id`, `confidence`, `t_start`, `t_end`, `rules[]` (документ, пункт, ссылка).

## 2. Запуск и использование

Сервер (Windows, Python 3.11, CUDA 12.8):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\start.ps1
```

Скрипт: предпроверка окружения и весов → один воркер API (один GPU-владелец) → настоящий прогрев и пробный
анализ → только после этого Cloudflare Tunnel; публичный адрес пишется в `logs\public_url.txt`.
Настройки — `deploy\.env` (ключ, пути к весам, режимы модулей). Веса скачиваются один раз заранее;
в рантайме сеть не используется (`HF_HUB_OFFLINE=1`, сетевой запрет внутри процесса Python).

Пользователь: открыть адрес → ввести ключ → перетащить `.mov` → дождаться статуса «готово» (1–5 минут) →
вердикт, лента времени с эпизодами, кадры «до/после», описание, норма, блок «что система не проверяет».
Отчёт можно выгрузить в JSON (схема ТЗ) и Markdown; сохранённый JSON открывается в режиме «Повторный просмотр».

## 3. Архитектура, подход, модели

```
UI (React) ─┐
            ├─ API (FastAPI): ключ, очередь, дедлайн, идемпотентность по sha256, честные статусы
жюри (curl) ┘        │
                     └─ Пайплайн (один GPU-воркер):
                        ingest (PTS, переменный fps) → detect (RT-DETRv2 + OWLv2) → track (роли по зонам)
                        → scene (состояния) → rules (правила) → VLM: кадр за кадром вопросы о состоянии сцены
                        (кто на стороне кассира, открыт ли сейф, что на столе, что в руках) + временная логика
                        → fusion (слияние источников, пороги, кадры-доказательства, описание, нормы)
```

Почему так: нарушение в этих видео отличается от нормы одной деталью — закрыт ли сейф, остались ли на столе
деньги или инкассаторская сумка после ухода кассира, мобильный или стационарный телефон в руке. Классификатор
по целому кадру этого не видит (замер: AUC 0,30–0,34), поэтому решение строится из наблюдаемых состояний и
переходов между ними; таймкод — момент перехода (начало нарушения).

| Модель | Назначение | Лицензия |
|---|---|---|
| Qwen/Qwen3-VL-4B-Instruct (4-bit) | вопросы о состоянии сцены по кадрам, проверка кандидатов | Apache-2.0 |
| PekingU/rtdetr_v2_r18vd | люди и предметы | Apache-2.0 |
| google/owlv2-base-patch16-ensemble | сейф, наличные, сумка (open-vocabulary) | Apache-2.0 |
| intfloat/multilingual-e5-small | поиск по нормам для ассистента проверяющего | MIT |

Библиотеки: PyTorch (BSD), Transformers (Apache-2.0), bitsandbytes (MIT), FastAPI (MIT), React (MIT),
cloudflared (Apache-2.0). Облачные AI-сервисы не используются; распознавания лиц нет, головы на кадрах-доказательствах
размываются.

## 4. Нормативные источники и принцип сопоставления

Источники — действующие акты НБРК на adilet.zan.kz:
- Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей в БВУ
  (постановление Правления НБРК от 29.11.2019 № 231) — https://adilet.zan.kz/rus/docs/V1900019680
- Правила организации охраны и устройства помещений банков второго уровня (постановление Правления НБРК
  от 24.02.2020 № 14) — https://adilet.zan.kz/rus/docs/V2000020075

Принцип: норма → требование → что из этого видно на записи → сигнал системы → событие. Подробно —
`norms/MAPPING.md`, `norms/SOURCES.md`, `norms/REVIEW_MATRIX.md`. Каталог `norms/catalog.yaml` содержит только
ссылки из сохранённых текстов; `python -m norms.validate` проверяет, что каждая цитата дословно есть в тексте
источника. Если подтверждённого пункта нет, нарушение выдаётся честно «без пункта» (FAQ 31), номера пунктов не
выдумываются. Статус сверки виден в интерфейсе («цитата сверена» / «не сверено с первоисточником»).

## 5. Распознаваемые типы

| Код | Тип | Что видно |
|---|---|---|
| V01 | Посторонний на стороне кассира / в кассовой зоне | второй человек на стороне кассы (клиент напротив — норма) |
| V02 | Кассир покинул рабочее место, оставив ценности без присмотра | после ухода кассира на столе остаются наличные |
| V03 | Сейф открыт без присмотра или за спиной работающего кассира | дверца сейфа открыта, у сейфа никого |
| V04 | Вход в кассовое помещение при открытых ценностях | человек входит, когда на столе наличные или открыт сейф |
| V05 | Мобильный телефон в руке кассира при работе с ценностями | мобильный (не стационарный) в руке на рабочем месте |
| V06 | Еда или напитки на рабочем месте с ценностями | кассир подносит еду или напиток ко рту |
| V07 | Нарушение порядка передачи инкассаторской сумки | сумка оставлена на столе без присмотра |
| V08 | Пересчёт наличных не в присутствии клиента | — |
| V09 | Личные вещи на рабочем месте кассира | куртка или личная сумка на кассовом столе |
| V99 | Иное видимое подозрительное действие | только подсказка, без правового вывода |

## 6. Ограничения и известные ошибки

Замер на 42 обучающих видео (разведочная оценка, не независимый тест; часть прогона): доля верных вердиктов
около 0,46, полнота около 0,46, медианная ошибка таймкода около 3 с. Это честные текущие цифры.

- Стационарный телефон на столе детектор иногда принимает за мобильный — ложные V05.
- Клиента напротив кассира модель иногда относит к стороне кассы — ложные V01.
- Открытую дверцу сейфа на кадре целиком модель видит плохо — пропуски V03.
- Время обработки 80–280 с на видео на одной RTX 4060; при пакете из нескольких видео одновременно задачи идут
  по очереди (один GPU-воркер).
- Типы в обучающих данных не размечены; эталонные типы подтверждает человек, предложения VLM эталоном не считаются.
- Устойчивость к другому ракурсу не проверена на реальной записи (зоны и правила не привязаны к пикселям).
- Система не проверяет: корректность проводок, суммы и подлинность банкнот, личность и полномочия людей,
  умысел, события вне поля зрения камеры.
