# frontend/ — веб-интерфейс Kassa Sentinel (A15)

Веб-интерфейс проверяющего: загрузка .mov → прогресс анализа → отчёт с вердиктом, эпизодами, таймкодами,
кадрами-доказательствами и нормами РК. **Vite 6 + React 18 + TypeScript 5.9 + Tailwind 3.4**.
Язык — русский; светлая и тёмная темы; адаптивная вёрстка от 375 px; есть печатная версия отчёта.

Офлайн-контур банка: шрифты (Inter, Manrope — `@fontsource-variable`, OFL-1.1) и иконки (`lucide-react`, ISC)
собираются в бандл, **CDN не используются** (в `dist/` нет внешних URL, кроме ссылок на нормы adilet.zan.kz).
ML-моделей во фронтенде нет: `models.json` = `[]`.

## Переработка интерфейса после стартовой сцены (A15)

База: `90083a0` (аудит 2055fc4 сохранён отдельными коммитами `4cd2317`, `90083a0`). Стартовая сцена (`UploadScreen`)
не тронута. Глобальные стили, `App`, `Header`, `ui.tsx` и чужие экраны — у U01 и U-ролей, их файлы не менялись.

**Объём — только файлы A15, ни за кем не закреплённые:**
- `JobScreen`, `Evidence`, `Lightbox`, `EpisodeNavigator`, `ReplayScreen`;
- стили — в модуле роли `src/components/a15.module.css`.

Как устроены стили:
- Цвета берутся из токенов U01 (`--ks-*`, внутри `.ks-ws`) с фолбэками на ту же палитру, поэтому одинаково выглядит
  и в сборке с U01, и без неё.
- Зелёного в этих компонентах нет. Красный — только событие и ошибка; янтарный — незавершённый анализ и
  предупреждения; ink — действия и справка.
- Визуальный язык стартовой сцены: сетка 28 px с радиальной маской, тонкие линии, Manrope, мягкое появление.

Что изменилось по экранам:
- **Экран задачи.**
  - До первого ответа — шапка как у экрана обработки (без скачка компоновки) и нейтральный скелет. Процентов и сроков нет.
  - Ошибка и незавершённый анализ — карточка «что произошло → что это значит → что можно сделать».
    - Ошибка получения: красная полоса и шапка. 403: главное действие «Настройки доступа»; повторная отправка файла
      здесь не поможет и не предлагается.
    - `failed`: янтарная; повторная отправка (U11) — главное действие.
  - Обрыв связи — янтарная плашка со счётчиком попыток и «Проверить сейчас»: один немедленный запрос, пауза
    backoff сохраняется.
  - Вход на странице задачи — пояснение над формой входа.
- **«До / после».**
  - Плитки выровнены по высоте (CSS subgrid), время — на плитке.
  - Промежуток «+4,0 с» считается по меткам кадров и показывается, только если оба кадра есть.
  - Честные плашки «кадра «до» нет» / «кадра «после» нет» с переходом к моменту.
  - Пометка «кадр из видео, без размытия» оставлена.
- **Подсветка A12.** Рамка получила тёмную подложку (видна на светлом фоне); подписи читаются на любом кадре.
  Цвет и текст — из данных сервера.
- **Лайтбокс.**
  - Лента кадров эпизода, сгруппированный масштаб (сброс — кнопкой или «0»).
  - Ловушка фокуса, возврат фокуса на кнопку, открывшую кадр; класс `ks-ws` на портале.
- **Навигатор эпизодов.**
  - Шкала просмотра — только наглядность: текущий эпизод красный, просмотренные — ink, не зелёные.
  - Название типа не обрезается.
  - «Смотреть эпизод» — главное действие.
- **Повторный просмотр.**
  - Пометка видна всегда.
  - JSON и видео — перетаскиванием или выбором. Видео можно добавить и после открытия отчёта (раньше — только до).
  - Есть «Открыть другой отчёт».

**Без изменений:** API, авторизация, опрос (интервал, backoff, пауза скрытой вкладки), маршруты, обработка ошибок
и смысл данных. Тексты и роли, на которые опираются e2e U01 и A15, сохранены.

## Фаза 2: доводка до боя (решения и замер для L2)

Сквозной сценарий: **загрузка → статус → вердикт → выбор события → переход в видео (точный момент, пауза на кадре) →
кадр → норма**, с последовательным просмотром нескольких событий. Новые экраны не добавлялись, кроме replay
сохранённого отчёта из п. 5 задачи.

### Состояния, которые не смешиваются
| Состояние | Как выглядит | Источник |
|---|---|---|
| Обработка | степпер по `stage`; процент только из `progress`; «прошло» по `elapsed_s`; **ETA нет**; пройденные стадии с фактической длительностью | A02, A03 |
| Ошибка | жёлтый «Анализ не завершён» + причина; если есть `meta.stages`, `candidates` или `partial` — подробный отчёт с панелью полноты | A01, A02 |
| Полный результат | зелёный «Нарушение не обнаружено» **только при подтверждённой полноте**: `analysis_complete` (A01), `meta.complete` (A03) или coverage ≥ 0,98 при всех обязательных стадиях ok/cached | A01, A03, A04 |
| Неполный | жёлтый «Анализ неполный» / пометка «НЕПОЛНЫЙ АНАЛИЗ»: coverage < 0,98; обязательная стадия не ok или покрыла < 0,9 записи; `degraded`, `deadline_exceeded_s`, `coverage_problem` с доказанным пробелом | A01, A03, A04 |
| Неизвестно | серый «Нарушение не обнаружено» + «ПОЛНОТА НЕ ПОДТВЕРЖДЕНА» (unknown ≠ «нет») | — |
| mock / fake | «Тестовый результат: модели не запускались» (`meta.mock`, `origin=mock`, FAKE PIPELINE) | A02, A03 |
| Demo / replay | лента «СИНТЕТИЧЕСКОЕ ДЕМО» / «ПОВТОРНЫЙ ПРОСМОТР: сохранённый отчёт»; не подменяют реальную загрузку и ошибку | UI |

Панель **«Полнота анализа»** показывает долю записи, причины, статус и фактическое время каждой стадии (`meta.stages`),
покрытие стадий (`meta.coverage` A03) и стадии, взятые из кэша.

### Карточка нарушения
- Название — каноническое из `norms/catalog.yaml` (A13). Запасная копия названий и `not_observable` — в `src/lib/catalog.ts`,
  плюс V09 «Личные вещи на кассовом столе».
- Кадры показываются без обрезки. Подсветка рамками из `meta.ui.evidence_overlays[].shapes` (A12) включается переключателем;
  рамки рисуются только на кадрах около пика.
- **«До / после»** для эпизодов-переходов (V02, V03, V07):
  - «до» — кадр сервера раньше `t_start`, иначе кадр из видео в браузере в `t_start − 2 с` с подписью «без размытия»,
    иначе кнопка перехода;
  - «после» — кадр в момент или после начала эпизода, с подсветкой.
- Норма:
  - бейдж «цитата сверена» — **только** при `verified: true`, иначе «цитата не сверена» и `status_ru` от A12;
  - `clause: null` → явное «без пункта», без выдуманных пунктов.
- Блоки «По видео не установить» (по типу) и «Что система не проверяет» (общий). Copilot необязателен.

### Флаги (рантайм, `dist/ui-config.json`, правятся без пересборки)
| Флаг | По умолчанию | Зачем |
|---|---|---|
| `seekPauses` | `true` | переход к событию ставит паузу на кадре таймкода |
| `episodePrerollS` / `episodePostrollS` | `2` / `1` | «Смотреть эпизод»: проиграть с запасом до и после |
| `beforeAfterTypes` | `["V02","V03","V07"]` | для каких типов показывать «до / после» |
| `beforeOffsetS` | `2` | «до» = `t_start − N` |
| `highlightMaxDtS` | `0.1` | рамки A12 (bboxes для кадра t_peak) рисуются только на кадре не дальше N с от `t_peak` (аудит 2055fc4: было 0.6) |
| `ptsOffsetMode` | **`"none"`** | ГИПОТЕЗА: `"meta_t0"` прибавляет `meta.video.t0_pts_sec` при перемотке. **Выключена до замера L2** |
| `showReviewHints` | `true` | пограничные моменты и кандидаты — отдельным блоком, вне вердикта |
| `pollIntervalMs` / `pollMaxIntervalMs` | `1500` / `10000` | опрос; потолок экспоненциальной паузы при сбоях сети (опрос не обрывается) |
| `pausePollingWhenHidden` | `true` | скрытая вкладка не опрашивает сервер |

### Надёжность
- Восстановление по `#/job/<id>` после перезагрузки. При 401 форма входа появляется прямо на странице задачи, и опрос
  продолжается.
- Опрос останавливается на done/failed/403/404. При сбоях сети пауза растёт, виден баннер «Нет связи».
- «Отправить этот файл повторно» после сбоя анализа (файл хранится только в памяти вкладки); «Повторить загрузку».
- Остальное — как в фазе 1: cookie-сессия + CSRF, Range-видео, клавиатура, 375 px, без CDN, ключ не в бандле, URL или
  localStorage.

### Команда замера для L2 (одна)
```bash
cd frontend && npm ci && npm run build     # dist раздаёт A02
E2E_BASE_URL=http://127.0.0.1:8000/ E2E_KEY=<ключ> E2E_VIDEOS=<папка .mov/.mp4> E2E_CHECK_PTS=1 \
E2E_LABELS=<labels.csv: file,label,second> E2E_OUT=e2e-ui-report.json \
PLAYWRIGHT_MODULE=<путь к playwright> node scripts/e2e-real.mjs
```
- **Что сравниваем.** Гипотезу `ptsOffsetMode` (`none` против `meta_t0`) — прямой сверкой кадров. Для каждого
  кадра-доказательства видео в браузере перематывается на `ts + δ` (δ ∈ ±1 с; добавляется `t0_pts_sec`, если он
  есть), уменьшенный кадр сравнивается с кадром сервера (средняя абсолютная разность). Решение:
  - лучший δ = 0 у подавляющего большинства кадров → оставить `none`;
  - лучший δ ≈ `t0_pts_sec` → включить `meta_t0`.
- **Выход** — JSON только с числами и кодами (ни кадров, ни описаний сцен). По каждому ролику:
  - время: `upload_s`, `time_to_result_s` (как видит проверяющий), `server_total_s`, время по стадиям;
  - состояние анализа: статусы стадий, `vram_peak_mb` (из `meta.stages`), `complete`, `coverage`;
  - события: `type_id`, `t`, `t_start`, `t_end`, `conf`, `frame_dt`, число норм и сверенных;
  - UI и видео: часы плеера после перехода к событию, HTTP-статус видео-маршрута и воспроизводится ли видео,
    `pts_check`, ошибки JS.

  Сводка: латентность p50/p90/max, гистограмма лучших δ, максимум VRAM; при `E2E_LABELS` — FP/FN и попадание
  таймкода ±3 с с пометкой «разведочно, не независимый тест».
- **Метрики качества по всему набору** (FP/FN, тип) — у A16; здесь — только то, что видит проверяющий в UI.
- **Имена с кириллической «Х»:** Playwright ≥ 1.56 молча не выставляет файл, если в пути кириллица. Скрипт передаёт
  такие файлы буфером с исходным именем (до ~50 МБ на файл).
- **Проверено на интеграционной ветке** (A02 fake-пайплайн, синтетические ролики ffmpeg, в том числе `Х-3.mp4`):
  2/2 ролика, лучший δ = 0 у обоих кадров, видео-маршрут 206, часы плеера после перехода = таймкоду, ошибок JS 0.

### Аудит интеграции 2055fc4 (что воспроизведено и исправлено в `frontend/`)
Проверено на живом A02 из `claude/integration-cloud` @ 2055fc4 с этим `dist` и синтетическими роликами ffmpeg
(fake-пайплайн A02 и mock-пайплайн A03):
- **Обёртка `partial` у `failed`.** A02 теперь отдаёт `partial = {code, complete, partial: <partial.json A03>,
  rejected_result: <отвергнутый отчёт>}`, а `image_base64` заменяет на `"<jpeg omitted>"`.
  - Раньше UI принимал обёртку за отчёт (голая карточка ошибки), а заглушку показал бы битой картинкой.
  - Теперь отчёт берётся из `rejected_result`, затем из `partial.partial`. Кадр без изображения — плашка
    «кадр не передан» с моментом, без подмены; в лайтбокс, «до/после» и JSON жюри он не попадает.
- **«До/после».** «После» больше не подставляет кадр раньше начала эпизода.
- **Подсветка.** Рамки A12 рисуются только на кадре `t_peak` (`overlay.timecode_sec`, допуск 0,1 с), а не на соседних
  кадрах.
- **«Недавние проверки».** Раньше там был зелёный «без нарушений» для неизвестной полноты и mock. Теперь история
  хранит `completeness`/`mock`; зелёный — только для полного не-mock результата.
- **Полнота и подписи.** Канонический `meta.coverage` A01/A03: доли стадий из `by_stage`, `coverage.complete=false` →
  неполный. Добавлена подпись стадии `refine` («Уточнение окон»).
- **Сверено с A02 2055fc4.**
  - Сессия: `POST /ui/v1/session {api_key|password}` → cookie `ks_session` (HttpOnly, Path=/ui/v1);
    `GET /ui/v1/session` → `csrf_token`.
  - Запросы: POST с `X-CSRF-Token` (analyze 200, ask 501 при выключенном Copilot); профиль `ui` у `/ui/v1/jobs/{id}`;
    видео `/ui/v1/jobs/{id}/video` → 206; `copilot/status` (available:false → панель скрыта).

## Путь пользователя

1. **Вход.** `GET /ui/v1/session` → 401 → форма «Вход для проверяющего». Ключ доступа (или пароль UI) →
   `POST /ui/v1/session {api_key, password}` → сервер ставит HttpOnly cookie и возвращает `csrf_token`.
   Ключ не сохраняется: его нет ни в localStorage, ни в URL, ни в бандле. CSRF-токен хранится только в памяти вкладки.
2. **Загрузка.** Drag&drop или выбор файла; проверяются расширение `.mov`/`.mp4`, MIME-тип и размер
   (`VITE_MAX_UPLOAD_MB`, по умолчанию 1024; лимит сервера A02 — 300 МБ). Реальный прогресс XHR `upload.onprogress`,
   скорость загрузки, отмена. `POST /ui/v1/analyze` (multipart, поле `file`) с заголовком `X-CSRF-Token`.
3. **Обработка.** Опрос `GET /ui/v1/jobs/{id}` (интервал из `ui-config.json`). Степпер (6 шагов) строится по `stage`
   (в том числе по русским подписям A03); процент — **только при наличии `progress` от сервера**; оставшееся время
   не прогнозируется (фаза 2). Показываются `queue_position`, `elapsed_s` и фактическая длительность пройденных стадий.
   Сетевые сбои — экспоненциальная пауза без обрыва; 401 — вход на этой же странице; 403/404 — понятная ошибка.
4. **Результат.**
   - баннер с формулировками ТЗ: «Обнаружены признаки возможных нарушений» / «Нарушение не обнаружено»;
   - плеер: только что загруженный файл играет локально (blob), повторно открытая задача — по
     `/ui/v1/jobs/{id}/video` (cookie + HTTP Range);
   - кастомная шкала: тепловая полоса индекса риска (`timeline`), интервалы эпизодов, пронумерованные маркеры
     (клик — перемотка), playhead, подсказка при наведении; горячие клавиши: Space — пауза, ←/→ — ±5 с,
     N/P — следующий/предыдущий эпизод (на самой шкале ←/→ — ±1 с, с Shift — ±5 с);
   - карточки эпизодов: тип и `type_id`, таймкод `mm:ss.s` (клик — перемотка и прокрутка к плееру), интервал,
     бейдж уверенности, описание, галерея кадров (лайтбокс: зум колесом, кнопками и двойным кликом, панорама,
     стрелки, Esc, кнопка «Перейти к моменту»), нормы (документ, пункт, раскрывающаяся цитата, ссылка на adilet,
     бейдж «цитата сверена» / «цитата не сверена» по `verified`, «без пункта»), блок «Как система пришла к выводу»
     (facts и источники rules / temporal / vlm / fusion);
   - справа: навигация по эпизодам, «Стоит просмотреть» (A12 `meta.ui.review_hints` — пограничные моменты ниже
     порога; в вердикт не входят, на шкале — серые ромбы), Copilot (при 501 скрывается), «Что система не проверяет» (ТЗ §7),
     технические детали (`meta.timings`, `meta.models`, версия);
   - экспорт: **JSON по схеме ТЗ** (для жюри — только обязательные поля), **полный JSON** (нормы, timeline, meta),
     **печать / PDF** (отдельные print-стили: шапка отчёта, раскрытые цитаты, URL ссылок, без плеера и чата).
5. **Пакетная проверка.** Можно выбрать или перетащить несколько файлов: они встают в очередь и загружаются по одному;
   статусы опрашиваются в фоне (пакет переживает переходы между экранами). По каждому файлу — вердикт, ссылка на отчёт;
   есть «Сводка JSON» (файл, job_id, вердикт, эпизоды — без кадров). Неподходящие файлы отбраковываются сразу.
6. **История.** Список «Недавние проверки» объединяет локальную историю (localStorage, только job_id, имя файла
   и вердикт) и серверную (`GET /ui/v1/jobs`).
7. **«О системе».** Принципы работы, схема пайплайна, API для автоматической проверки (curl с адресом сервера),
   типы V01–V08/V99, модели и лицензии (из `meta.models` последнего анализа или список по архитектуре),
   бейдж «Работает полностью локально».

### Правила честности интерфейса
(Фаза 2 уточнила: три состояния полноты — см. таблицу «Состояния» выше; ниже — исходные правила фазы 1.)
- **Failed или неполный анализ никогда не показывается зелёным.**
  - `status: failed` → жёлтый баннер «Анализ не завершён»; если A02 передал `partial`, показывается найденное до сбоя.
  - `done` + признаки неполноты (`meta.partial | incomplete | degraded | timed_out`, `complete: false`,
    непустые `skipped_stages | stages_skipped | failed_stages`, предупреждения с partial / timeout / skipped /
    неполн / таймаут / пропущ) → «Анализ неполный», нужен ручной просмотр.
  - Зелёный «Нарушение не обнаружено» — только для `done` + `no_violation` с **подтверждённой** полнотой (фаза 2).
- «Уверенность» подписана как внутренняя оценка модели, а не вероятность и не точность. Кривая риска подписана
  как «индекс риска (не вероятность)».
- Тексты описывают только видимое; блок «Что система не проверяет» есть на каждом отчёте.

## Какие маршруты использует UI (сверено с веткой A02)

| Метод и путь | Авторизация | Назначение |
|---|---|---|
| `GET /ui/v1/session` | cookie | 200 `{authenticated, csrf_token}` или 401 `{authenticated:false, password_login}` |
| `POST /ui/v1/session` | тело `{api_key, password}` | вход → HttpOnly cookie (path `/ui/v1`) + `csrf_token` |
| `DELETE /ui/v1/session` | cookie | выход |
| `POST /ui/v1/analyze` | cookie + `X-CSRF-Token` | multipart `file` → `{job_id}` |
| `GET /ui/v1/jobs/{id}` | cookie | статус и результат (схема ТЗ + доп. поля; у failed — `partial`) |
| `GET /ui/v1/jobs?limit=20` | cookie | серверная история |
| `GET /ui/v1/jobs/{id}/video` | cookie | видео для `<video>` (Range) |
| `POST /ui/v1/jobs/{id}/ask` | cookie + `X-CSRF-Token` | Copilot (A14) `{question, history:[{role,text}]}` → `{answer, sources?}`; 501 → панель скрыта; 409/503/504 → понятные сообщения |
| `GET /ui/v1/copilot/status` | cookie | `available:false` → панель Copilot не показывается (без ожидания 501) |
| `GET /ui/v1/jobs/{id}/report` | cookie | «Заключение .md» (A14, работает без LLM); 404 → сообщение |
| `/api/v1/*` | `X-API-Key` | запасной путь, если `/ui/v1` выключен (404/405): ключ из «Настроек», только в памяти вкладки |

Все пути собраны в `src/api/client.ts` → `ENDPOINTS`. При 403 на POST (устарел CSRF после перезапуска сервера)
сессия перечитывается и запрос повторяется один раз. При 401 на `/ui/v1/*` и наличии ключа в памяти запрос
повторяется через `/api/v1/*`.

## Ограничения

- Воспроизведение зависит от кодека и браузера: H.264 в Chrome и Edge играет, в сборке Chromium из Playwright — нет;
  HEVC (частый в .mov с телефонов) многие браузеры не декодируют. Плеер перебирает источники: локальный файл →
  `/ui/v1/jobs/{id}/video` (A02 отдаёт `preview.mp4`, если исходник был перекодирован) → blob по API-ключу. Если ни один
  не играет, показывается понятное сообщение (проверено на A02: локальный blob → 206 с сервера → сообщение). Отчёт
  без видео полностью работоспособен: кадры-доказательства и таймкоды остаются. **Для A02/A04:** перекодирование
  в H.264 `preview.mp4` снимает проблему HEVC.
- Факты и источники для «Как система пришла к выводу» берутся по порядку: `violations[].facts/sources` →
  `meta.ui.evidence_overlays[]` от A12 (по `violation_index`; `sources` — словарь источник→вес; там же `vlm`:
  confirm/reject/unsure → бейдж «VLM подтвердила/не подтвердила») → `meta.events[]` → предложения `description`.
- Стадии A03 приходят русскими подписями («Поиск людей и объектов», «Проверка VLM»…) — степпер сопоставляет их
  по ключевым словам; флаги полноты A03 (`meta.complete/partial/degraded`) учитываются в вердикте.
- История в localStorage — только на этом устройстве. Серверная история зависит от `GET /ui/v1/jobs`.
- Демо-нормы — заглушки; реальные ссылки приходят только из `norms/catalog.yaml` через сервер.

## Для интегратора

1. **Раздача.** A02 уже отдаёт `frontend/dist` на `/` (`frontend_dir: frontend/dist`). В Docker (A17) нужен
   этап `cd frontend && npm ci && npm run build` (Node ≥ 18.18); `node_modules` и `dist` в git не попадают (`.gitignore` A01).
2. **A02.** Маршруты из таблицы выше совпадают с веткой A02. При первом запуске ветки A02 в чистом venv загрузка
   падала с 500 из-за отсутствия `python-multipart`; в `backend/api/requirements.txt` (коммит A02 c33e485) он уже есть —
   A17 нужно ставить зависимости именно из этого файла.
3. **A03 / A12 (fusion) / A01.** Пожалуйста, отдавайте:
   - `meta.duration_sec` — для шкалы, если видео не загрузилось;
   - флаги неполноты (`meta.partial` или `meta.skipped_stages`) — для честного вердикта;
   - по возможности `violations[].facts[]` и `violations[].sources[]` (или `meta.events[]` с `type_id`, `t_peak`,
     `source`, `facts`) — для блока «Как система пришла к выводу».

   Сам контракт не меняется: это доп. поля через `meta` / `extra`.
4. **A13 (нормы).** UI показывает `rules[]` (или `rule`) как есть: `document`, `clause`, `quote`, `url`, `verified`.
5. **A14 (Copilot).** Формат сверен с веткой A14 (`copilot/INTEGRATION.md`): `POST …/jobs/{id}/ask`
   `{question, history:[{role, text}]}` → `{answer, sources}`; UI сначала спрашивает `GET …/copilot/status`.
6. **A18 (питч).** Скриншоты синтетического демо лежат в `frontend/screenshots/`; живое демо открывается по `/?demo=1`.
