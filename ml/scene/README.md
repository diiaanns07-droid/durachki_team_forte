# ml/scene — состояния сцены (A08)

Модуль считает по каждому сэмплу `clip.times` все 17 сигналов из `SIGNALS`: сейф, дверь, наличные, сумку, присутствие людей, движение, позу. Сигналы сглажены HMM из двух состояний. Главное правило: **«не обнаружили» ≠ «отсутствует»**. Значение, не подтверждённое наблюдением, помечается как неизвестное. В составные правила неизвестное не попадает ни как 0, ни как 1.

Модуль работает только на CPU и только локально. Нейросетей и весов у него нет: ему достаточно детекций A05, треков и зон A06, позы A07 и кадров A04. Обучаемый вариант необязателен (см. ниже).

## Публичный интерфейс

```python
from ml.scene import scene_states                     # сигнатура заморожена контрактом v1
states = scene_states(clip, dets, tracks, zones, pose_states)   # list[SceneStateEx], len == len(clip.times)

from ml.scene.core import scene_states_with_trace      # то же + trace (сырые признаки, ROI, предупреждения)
from ml.scene.types import SceneStateEx, signal_value, is_known
from ml.scene.io import dump_states, load_states       # JSON для кэша A03 / графиков
from ml.scene.types import predicate, signal_status    # фаза 2: True/False/None и true|false|unknown|occluded
from ml.scene.intervals import intervals, coverage     # фаза 2: интервалы для A09, покрытие для meta.coverage
```

CLI: `python -m ml.scene.report` (PNG и index.md с GT), `python -m ml.scene.ablation`, `python -m ml.scene.l2_bench`, `python -m ml.scene.plot`, `python -m ml.scene.train_signals`.

### `SceneStateEx`: совместимое расширение контракта без изменения файлов A01

`SceneStateEx` — подкласс `SceneState`, поэтому `isinstance(s, SceneState)` истинно, а `t` и `signals` работают как раньше. Новые поля:

| поле | смысл |
|---|---|
| `signals[name]` | лучшая оценка P(состояние=1). Без наблюдений плавно возвращается к априорной вероятности из `config.yaml` (низкой для «рисковых» сигналов), а не к 0.5 |
| `conf[name]` | 0..1, насколько значение подтверждено наблюдением, с затуханием `exp(−Δt/1 с)` |
| `known[name]` | `conf ≥ 0.5`. Значение можно использовать как факт «да» или «нет» |
| `visibility[name]` | 1 − окклюзия ROI людьми (для `safe_open`, `door_open`, `cash_visible`) |
| `provenance[name]` | источник: `det`, `roi`, `geom`, `traffic`, `track`, `pose`, `det_fallback`, `colour`, `learned`, `derived` или `none` (несколько — через «+») |
| `observed` | наблюдения вне `SIGNALS`: `unknown_person_in_cashier_area`, `workplace_empty(+_conf)`, `workplace_track_lost`, `safe_unattended` |
| `quality` | 0..1, качество кадра: резкость, экспозиция, контраст. Берётся из `clip.quality`, иначе считается сам |

Для правил A09 и A12 есть хелпер `signal_value(state, "safe_open")`: он возвращает `None`, если значение неизвестно. Для обычного `SceneState` без расширения возвращает значение как есть.

### Несовместимость вне моей зоны (для L2/A03)

**`backend/pipeline/serde.py::load_state`** восстанавливает только `SceneState(t, signals)`. При `cache.normalize_outputs: true` (по умолчанию) каждый выход стадии проходит этот JSON-roundtrip, и поля `SceneStateEx` теряются: `known`, `conf`, `status`, `why`, `observed`, `quality`, `pred*`. A09 получает «голые» значения и считает неизвестное фактом.

- **Вход:** состояние A08 с `known["cashier_present"] = False`, `signals["cashier_present"] = 0.79` (трек пропал).
- **Ожидается:** после roundtrip `known` сохранён; `ml.rules.signals.build_series` даёт `NaN`.
- **Факт:** `SceneState(t, signals)` → `build_series` даёт 0.794 как наблюдённое.

Предложение для A03: в `load_state`, если в словаре есть `known`/`conf`, собирать `ml.scene.types.state_from_dict(d)` (подкласс `SceneState`). Сериализация туда и обратно уже проверена тестом `test_json_roundtrip_keeps_unknown_gating_fields`. Альтернатива — не нормализовать стадию `scene`.

Пока это не исправлено, A09 в пайплайне видит только значения. Неизвестное в них консервативно: presence держит последнее наблюдение и стремится к априорной вероятности 0.5–0.6, рисковые сигналы — к низкой. Но различие unknown/false теряется: `insufficient_context` и `coverage` у A09 перестают работать.

## Фаза 2: статусы, предикаты для A09, гипотезы для L2

### Явные статусы: false ≠ unknown ≠ occluded

У каждого сигнала в `SceneStateEx` есть `status[name]`: `true`, `false`, `unknown` или `occluded`. Причина неизвестного лежит в `why[name]`: `dark`, `low_quality`, `occluded`, `track_lost`, `no_zone`, `role_unknown`, `no_detector`, `no_pose`, `no_evidence`, `frames_unavailable`.

- «Нет» ставится только при наблюдении: стол виден, детектор работал, кадр годный.
- Не увидели деньги, человека или кисть — это `unknown`. Если ROI закрыт человеком — `occluded`.
- Трёхзначная логика на массивах лежит в `tri.py`: И/ИЛИ никогда не превращают неизвестное в 0.

### Предикаты для A09 (`pred`, `pred_status`, `pred_why`)

Это аддитивный слой: legacy-`SIGNALS` фазы 1 не меняются. Статусы те же: `true`, `false`, `unknown`, `occluded`. Хелпер `predicate(state, name)` возвращает `True`, `False` или `None` (неизвестно ≠ False). Интервалы: `ml.scene.intervals.intervals(states)`.

| предикат | true, когда | тип-подсказка |
|---|---|---|
| `cashier_left_workplace` | уход кассира подтверждён: трек исчез у края кадра или в двери, либо виден вне рабочего места. Начало интервала — момент перехода | — |
| `cash_left_after_leave` | в окне [t_ухода, t_ухода + 5 с] наличные **на столе** (desk/cash_tray) видны в ≥ 2 сэмплах. Купюры в руках клиента не считаются | V02 |
| `bag_left_after_leave` | в том же окне сумка лежит на столе или в зоне кассы, и её никто не держит | V07 |
| `safe_open_after_leave` | в том же окне сейф открыт | V03 |
| `safe_open_while_working` | сейф открыт ∧ кассир на месте ∧ у сейфа никого, ≥ 3 с | V03 |
| `outsider_cashier_side` | на стороне кассы (по опорной точке) человек с явной ролью `visitor` или пришедший со стороны клиента, ≥ 1 с. Клиент напротив (точка в `client_area`) и наклон над столом (точка на столе) не учитываются. Человек с неизвестной ролью — `unknown` | V01 |
| `second_person_client_side` | ≥ 2 человек на стороне клиента во время обслуживания, ≥ 2 с. Трактовка «второго постороннего» неоднозначна — решает A09 | V01 |
| `entry_while_valuables_open` | вход на сторону кассы человека, пришедшего со стороны клиента, когда сейф открыт или наличные на столе. Вход сотрудника с неизвестной ролью — `unknown` | V04 |
| `mobile_phone_in_hand` | поза «телефон в руке» **и** рядом с кассиром виден `cell_phone`, не стоящий неподвижно (стационарный телефон отфильтрован) | V05 |
| `eating_drinking_with_object` / `eating_at_workplace_with_valuables` | поза **и** виден `cup`/`bottle`/`food` (рука у лица без предмета — `unknown`). Второй предикат дополнительно требует ценности и кассира на месте | V06 |
| `personal_item_on_desk` | `bag`/`backpack`/`handbag`/`jacket`/`coat` на столе ≥ 2 с | V09 (по спецификации; нет ключа в каталоге — A12 сводит к V99) |
| `bag_left_unattended` | инкассаторская сумка видна, никого рядом ≥ 3 с. Сумку держат — `false`; сумки не видно (могла уйти в сейф) — `unknown` | V07 |
| `lights_off` | медианная яркость кадра ниже max(28, 0.4 × типичной) ≥ 1 с. Это условие сцены: в темноте предикаты «после ухода» берут последнее известное состояние, без него — `unknown(dark)` | — |

**Роли** определяются по поведению за весь ролик. Сотрудник — тот, кто дольше всех работает со стороны кассы (≥ 5 с), либо тот, кому A06 дал явную роль. Порядок появления значения не имеет: кассир может войти через дверь в первые секунды. Второй человек без истории в `client_area` получает неизвестную роль — он не сотрудник и не посторонний.

**События и интервалы.**
- `trace["events"]`: события `leave` (с решениями по окну и `t_left_desk`) и `entry` (с `valuables_open`).
- `trace["intervals"]`: true-интервалы каждого предиката. Дребезг склеивается (`max_gap_s` = 0.6), короткие true становятся `unknown`.
- `t_start` интервала — момент перехода. Политика `t_peak` (`onset`/`mid`/`max`) задаётся в `predicates.timecode`; её выбирает замер L2.

**Покрытие.** `intervals.coverage(states)` даёт долю известного по каждому предикату и причины неизвестного. A03/A12 кладут это в `meta.coverage`: неполный анализ ≠ no_violation.

### Гипотезы: флаги в `config.yaml`, все по умолчанию выключены до замера L2

| ID | флаг | что меняет |
|---|---|---|
| H1 | `safe.cluster_mode` / `door.cluster_mode: kmeans2` | два кластера вида ROI по **всему** ролику (2-means, симметрично) вместо «эталона начала». Имена кластеров — только по свидетельствам |

### Абляция state machine и сглаживания (синтетика, демо-данные)

Команда: `python -m ml.scene.ablation`. Отрицательные случаи:
- N1 — сейф открыт с начала и закрыт до ухода;
- N2 — сейф заслонён, кассир ушёл;
- N3 — трек пропал посреди рабочего места при деньгах на столе;
- N4 — два сотрудника;
- N5 — клиент напротив наклоняется над столом.

Положительные: P1 — ушла, деньги на столе; P2 — ушла при открытом сейфе.

| вариант | FP (из 5) | FN (из 2) | ошибка onset, с |
|---|---|---|---|
| hmm (по умолчанию) | 0 | 0 | 0.0 |
| hysteresis | 0 | 0 | 0.0 |
| none (без сглаживания) | 0 | 0 | 0.0 |
| naive: не увидели = нет, пропавший трек = ушёл, первые кадры = закрытый сейф, «не кассир» = посторонний | 3 (N1, N3, N4) | 1 | 0.0 |

Вывод относится только к синтетике: на этих случаях ложные срабатывания убирают защиты unknown/ролей/эталона, а метод сглаживания не важен. Точность на реальных роликах даёт только замер L2.

**Метрики (по видео):**
- TP/FN/FP/TN, где «кандидат» — есть true-интервал нарушающего предиката;
- попадание таймкода hit@2s и hit@5s и медианная ошибка для политик `onset`/`mid`/`max`; дубли с конфликтом таймкодов исключены;
- типы-подсказки (разметки типов нет — смотрит человек);
- доля известного;
- латентность A08 на ролик;
- пик VRAM (H2);
- FP по терцилям длительности — проверка ловушки «длинный ролик — больше шансов на ложный пик».

Все 42 ролика уже видели в разведке, поэтому это **не независимый тест**. Длительность, позиция в ролике и имя файла признаками не являются.

## Как считаются сигналы

| сигнал | «да» подтверждается | «нет» подтверждается | иначе — неизвестно |
|---|---|---|---|
| `safe_open` / `door_open` | детекцией `*_open`; сменой вида ROI, если удалось установить, какой из двух видов «открыт»; для двери — проходом человека через зону двери | детекцией `safe`/`door`; тем же видом ROI | вид не менялся и детекций нет; ROI перекрыт; кадр плохой |
| `cash_visible` | детекцией `cash` на столе/лотке (1.0) или на стороне кассира (0.8); купюры в `client_area` и вне зон не считаются, без зон место не проверить → `unknown`; цвето-формовый классификатор купюр даёт только слабое свидетельство (conf ≤ 0.4) | стол виден **и** детектор работал **и** цветовой признак молчит | стол закрыт людьми, плохой кадр, нет детекций в видео |
| `cash_bag_visible` | детекцией `cash_bag`; зелёный блоб — слабо | только слабое «нет» (сумку легко не увидеть) | — |
| `cashier_present` | виден трек с ролью кассира | все «кассироподобные» треки подтверждённо ушли (см. ниже) | трек потерян |
| `cashier_in_workplace` | кассир в `cashier_area` (без неё — расширенный `desk`) | кассир виден вне рабочего места или его уход подтверждён | трек «растворился» посреди рабочего места; нет зоны; плохой кадр |
| `outsider_in_cashier_area` | в зоне человек с явной ролью `visitor` от A06 **или** с историей в `client_area` (пришёл со стороны клиента); инкассатор исключён; клиент на своей стороне (членство в `client_area` ≥ членства в зоне кассира) не учитывается | в зоне только сотрудники с явной ролью или один доминирующий трек со стороны кассы (если явного кассира нет), либо никого | человек с неизвестной ролью: заполняется `observed.unknown_person_in_cashier_area`, outsider остаётся неизвестным |
| `collector_present` | роль `collector` или трек с сумкой рядом | все видимые люди — с известной ролью | — |
| `n_persons` | целое, медиана по 5 сэмплам; `conf` = качество × «детектор работал» | | |
| `workplace_unattended_with_cash` | трёхзначное И: наличные «да» (известно) ∧ рабочее место пусто (известно, уход подтверждён) не меньше `min_s` = 3 с. Помечается весь интервал с самого начала (офлайн) | наличных нет (известно) или рабочее место занято (известно) | любой операнд неизвестен → значение 0, `known=False` |
| `motion_energy` | `clip.quality` или межкадровая разность | | |
| `phone_*`, `eating_drinking`, `hands_hidden`, `cashier_facing_away`, `handover_motion` | из `pose_states` (A07); `conf` берётся из `pose_state.conf`, если есть | | без позы — слабый det-фолбэк ×0.7, `conf` ≤ 0.3 |

**Уход подтверждён**, только если трек исчез у края кадра или в зоне двери, либо был виден вне рабочего места. Трек, исчезнувший посреди рабочего места, означает «неизвестно», а не «ушёл». Трек, который «возник» посреди места, мог стоять там и раньше: 1.5 с до его появления тоже неизвестны. Режим «только детекции, без треков» уход подтвердить не может, поэтому в нём `unattended` не срабатывает.

### Сейф и дверь: начало видео не считается эталоном «закрыто»

1. **Эталон A** — маскированная медиана первых N чистых кадров: людей у ROI нет, качество кадра хорошее. Его состояние неизвестно, это просто «как было в начале».
2. **Изменение вида**: `d(t) = 1 − CS-SSIM(ROI_t, A)`. Кропы z-нормированы, а из SSIM убран яркостный член, поэтому общий сдвиг освещения и мягкие тени изменением не считаются. Люди маскируются; кадр с окклюзией больше `occlusion_max` в расчёт не идёт, и HMM держит прежнее состояние. Дрожание камеры компенсируется через phase correlation.
3. **Состояние B** — альтернативный вид, устойчивый не меньше 1 с и внутренне согласованный. Короткие или несогласованные изменения (проход человека, тень, шум) состоянием не считаются.
4. **Какое состояние «открыто»**, решают только абсолютные свидетельства:
   - детекции `safe_open`/`safe` в кадрах каждого состояния;
   - симметричный слабый априор формы: у открытого вида больше тёмного проёма относительно окружения и вертикальная кромка дверцы вне контура. Априор ограничен ±1.5 логита и работает только для сейфа.

   Если свидетельств нет, `label_conf = 0` и сигнал остаётся неизвестным. Сейф, открытый с первого кадра, поэтому не превращается в «закрытый эталон».
5. **Итог**: в логит-пространстве суммируются вид, прямые детекции и, для двери, проходы людей. Затем — HMM forward-backward: офлайн, переходы асимметричны и сходятся к априорной вероятности.

ROI берётся из зон A06 (`safe`, `door`, `desk`, `cash_tray`, `cashier_area`, `client_area`). Если зоны нет — из медианного бокса уверенных детекций. Пиксельные координаты нигде не захардкожены.

## Запуск

```bash
pip install -r ml/scene/requirements.txt
python -m pytest ml/scene -m "not gpu and not slow" -q        # 36 тестов, синтетика, без GPU и весов

# графики сигналов (сплошная линия — подтверждено, пунктир — неизвестно, красная — GT-секунда)
python -m ml.scene.plot --cache cache/<sha> --out signals.png --gt 22
python -m ml.scene.plot --video data/X-1.mov --out signals.png --gt 22   # посчитать на лету

# необязательное дообучение по ПРОВЕРЕННЫМ меткам
python -m ml.scene.train_signals --labels data/scene_labels.csv --videos data/videos \
    --out weights/scene/scene_signals.json [--model lr|mlp] [--zones-json data/scene_zones.json]
```

### Формат `data/scene_labels.csv`

```
video,signal,t_start,t_end,value,verified
X-1.mov,safe_open,0,12.5,0,1
Х-3.mov,safe_open,12.5,30,1,1     # кириллическая «Х» нормализуется: x-3
X-7,cash_visible,4.2,,1,1         # пустой t_end — точечная метка (ближайший сэмпл)
```

- `signal` — одно из `safe_open`, `door_open`, `cash_visible`; `value` — 0 или 1.
- `verified` — 1, true, yes или «да»: строку проверил человек. Непроверенные строки игнорируются; использовать их можно только с флагом `--allow-unverified`.
- Неразмеченные участки в обучение не попадают: неизвестное ≠ 0.

Обучение использует group k-fold по видео: одно видео целиком попадает в один фолд. В JSON сохраняются `cv.auc` и `reliability = 2·(AUC − 0.5)`. Модель смешивается с ручной фузией в логит-пространстве с весом `learned.weight` = 0.5. Модель не загружается, если `SENTINEL_MOCK=1` или файла нет. Формат — JSON без pickle, в git не коммитится (`weights/` в `.gitignore`).

## Конфиг и переменные окружения

## Ограничения (честно)

- Пороги откалиброваны только на синтетике. На реальных роликах их нужно настроить по графикам `plot` (`roi_center`, `roi_scale`, `min_state_s`, `occlusion_max`, `unattended.min_s`).
- Без детекций A05 (`safe`/`safe_open`) сейф, который не менял вид за всё видео, остаётся неизвестным. Это сделано намеренно.
- Для двери априор формы выключен: у стеклянной двери нет надёжного направления «открыто или закрыто». Без детекций `door_open`/`door` и без проходов людей дверь остаётся неизвестной.
- Цвето-формовый классификатор купюр сам по себе не даёт `known`, потому что белые документы и упаковки похожи на купюры.
- Роли людей определяются по поведению, зонам и сумке; лица не используются. Без зон `cashier_area`/`client_area` посторонний не подтверждается.
- Сильная перспектива при другом ракурсе: членство человека в зоне считается по точке на 0.6 высоты бокса (`anchor_y`). Для наклонной камеры, возможно, лучше 0.8–0.9.
- **Фаза 2.**
  - H2 (SigLIP2) написан по API из скриптов L1 (transformers 5.20.1), но реальной загрузкой здесь не проверен: весов и torch нет. Первый прогон `l2_bench --variants baseline,H2` у L2 — это и smoke.
  - `second_person_client_side` — моя трактовка «второго постороннего во время обслуживания»; пусть A09 решит, брать ли его.
  - Подсказка V09 («личные вещи») взята из спецификации; ключ должен быть в `norms/catalog.yaml` (A13), иначе A12 сводит к V99.
  - Яркость кадра используется только как условие «свет выключен» (заморозка и `unknown(dark)`), а не как признак нарушения.

### Принятые решения (автономно)

- **Фаза 2.**
  - Спецификация поведения команды реализована в новом слое предикатов. Legacy-сигналы не трогал, чтобы не включать новый режим без замера.
  - Все алгоритмические изменения (H1–H6) — флаги, по умолчанию выключены.
  - Исключения, включённые по умолчанию:
    - исправление задержки ухода: трек больше не продлевается после последнего бокса, раньше таймкод опаздывал на 0.4 с;
    - калибровка `cash.det_absent_c` = 0.4, чтобы «нет наличных» на видимом столе было известно, как и описано в фазе 1;
    - порог стационарного телефона.
  - Моки только в тестах. Именователь в проде при ошибке выключается и не подменяется моком.

- Неизвестное в `signals` — это posterior HMM, который сходится к априорной вероятности. Это консервативно для потребителей, не читающих `known`: априорная вероятность рисковых сигналов низкая.
- `outsider_in_cashier_area` исключает инкассаторов: их присутствие — отдельный сигнал `collector_present`.
- `workplace_unattended_with_cash` по умолчанию не включает открытый сейф (`unattended.include_open_safe: false`), чтобы не путать V02 и V03. Открытый сейф идёт отдельно в `observed.safe_unattended`.
- Обучаемый вариант смешивается с ручной фузией (вес 0.5), а не заменяет её: меток мало.
