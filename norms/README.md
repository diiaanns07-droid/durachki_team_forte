# norms/ — нормативная база РК и каталог типов нарушений (A13)

Каталог `catalog.yaml` даёт для каждого типа V01–V09 и V99 название, наблюдаемые и ненаблюдаемые
признаки, исключения, короткий шаблон объяснения, синтетические примеры и нормы РК (`rules[]` в форме
`RuleRef`). Ещё в модуле есть загрузчик с fallback, валидатор схемы и цитат, поиск пунктов-кандидатов
(`norms.pick`), импорт полных текстов (adilet или ветка L1), review-матрица, чек-лист для человека
и сохранённые фрагменты источников для RAG (A14).

## Фаза 2: что изменилось и почему (решения A13)

- **Каталог приведён к спецификации команды.** V01 — «Посторонний на стороне кассира / в кассовой
  зоне» (клиент напротив — норма). V02 — уход оценивается по состоянию стола и сейфа в окне после
  ухода. V03 включает «работа при открытом сейфе за спиной». V04 переименован в «Вход в кассовое
  помещение при открытых ценностях»: открытая дверь сама по себе — не нарушение. V05 — мобильный
  (не стационарный) в руке. V07 — из рук в руки и сразу в сейф — норма. ID и схема сохранены.
- **Новый тип V09 «Личные вещи на рабочем месте кассира» — `candidate`.** В выдаче найден п. 12
  НБРК № 231: личные вещи работников хранятся вне кассового узла. Применимо, только если касса — часть
  кассового узла и вещь принадлежит работнику; по видео не устанавливается ни то, ни другое.
- **Нормы найдены для V02 (п. 22), V08 (п. 20) и V09 (п. 12)**, все — из поисковой выдачи, `verified: false`
  (п. 22 добавлен после аудита, см. ниже). Для V01, V03–V07 настоящего пункта, прямо относящегося
  к поведению, не найдено. Они остаются «без пункта, без правового вывода» (FAQ 32 допускает источник
  без точного пункта, но ничего не натягиваем).
- **Статусы раздельно** в `rule_checks`: `quote_level` (где сохранена цитата),
  `quote_checked_by_human`, `applicability_checked_by_human`. `verified: true` валидатор допускает только
  при полном тексте и сверке цитаты человеком; `legal_status: confirmed` — только после проверки
  применимости человеком.
- **Синтетические примеры** `positive` / `negative` / `unknown` у каждого типа. `unknown` обязательно
  содержит `null`-сигнал (unknown ≠ false). Это спецификация для тестов A09/A12, не реальные сцены.
- **`python -m norms.pick`** ищет пункты-кандидаты по `pick_keywords.yaml` и показывает, в каком пункте
  полного текста стоит каждая цитата каталога (`--check-catalog`). Человек подтверждает.
- **Полные тексты L1** подхватываются без checkout: `python -m norms.fetch --git-ref origin/data/norms-sources`.
  На 2026-10-17 08:25 UTC ветки `data/norms-sources` в origin не было.
- В модуле нет режимов, которые нужно измерять на видео: это данные и CPU-утилиты. Новый тип V09 влияет
  на детекцию только если A09 начнёт его выдавать — это решение и флаг A09.

## Главное о достоверности (прочитать до использования)

- **adilet.zan.kz и все зеркала из среды разработки были недоступны** (сетевая политика окружения:
  403 на `adilet.zan.kz`, `zakon.uchet.kz`, `prg.kz`, `online.zakon.kz` и др.). Работал только поиск.
  Поэтому `sources/*.md` — фрагменты из поисковой выдачи (`retrieval: search_snippets`), а не полные
  тексты, и у всех норм `verified: false`.
- Порядок рассуждения: действующая норма → условия применимости → наблюдаемое действие. Тип без
  подтверждённой нормы получает `legal_status: disabled`: норма к нему не прикрепляется (`rules: []`).
  Сейчас `candidate` у **V02** (п. 22 НБРК № 231: не покидать рабочее место до окончания обслуживания
  клиента), **V08** (п. 20 и подп. 4 пункта о выдаче: пересчёт в присутствии клиента) и **V09** (п. 12:
  личные вещи вне кассового узла). Остальные типы — `disabled`, и у каждого записано, почему.
- Телефон, еда, открытая дверь или второй человек в кадре сами по себе не нарушение. По видео нельзя
  установить допуск и личность. Такие случаи перечислены в `exclusions`, общих и по типам.
- `python -m norms.validate` проверяет схему и **целостность цитат** (цитата есть в сохранённом
  источнике). Это не юридическая верификация: действие редакции и применимость проверяет человек.
- `clause: null` не означает ложный источник. Это ссылка на документ без установленного номера пункта,
  а уровень проверки указан в `rule_checks`.

## Публичный API

```python
import norms
cat = norms.load_catalog()          # замороженная сигнатура; dict с ключами version, types, documents, exclusions, levels
norms.legal_status("V08")           # "confirmed" | "candidate" | "disabled"
norms.rule_refs("V08")              # list[dict] ровно с ключами RuleRef; для disabled → []
norms.exclusions("V05")             # общие + типовые «само по себе не нарушение»
norms.render_description("V08", 22.4, ["клиента у окна нет"])  # по description_template
norms.type_name("V01"); norms.get_type("V42")                  # неизвестный id → V99
norms.legal_basis("V08")            # {status, note, rules, checks, exclusions, disclaimer} — блок для UI/meta
norms.examples("V02")               # синтетические примеры: kind, facts, signals (null = неизвестно), expected
norms.catalog_source()              # "yaml" | "fallback" — для meta.warnings
```

Схема типа (совместима с преамбулой, новые поля можно игнорировать):
`name, observable[], not_observable[], description_template ({t}, {facts}), severity, rules[]` +
`legal_status, legal_note, exclusions[], examples[], rule_checks[] (по одному на норму: quote_level,
quote_source, quote_checked_by_human, applicability_checked_by_human, currency, applicability,
conditions_visible[], conditions_not_visible[]), research_candidates[]`.
Элементы `rules[]` содержат ровно `document, clause, url, quote, verified`, поэтому `RuleRef(**r)` работает.

## Команды

```bash
python -m norms.validate                 # схема + целостность цитат + сверка fallback; код возврата 0/1
python -m norms.validate --strict        # предупреждения (verified:false и т.п.) считать ошибками
python -m norms.validate --json          # отчёт для UI/CI
python -m norms.validate --write-fallback --write-matrix  # после правки catalog.yaml
python -m norms.fetch [--dry-run] [id]   # НА МАШИНЕ С ИНТЕРНЕТОМ: полные тексты adilet → sources/*.md
python -m norms.fetch --git-ref origin/data/norms-sources   # импорт текстов L1 из ветки (без checkout)
python -m norms.fetch --from-dir norms_fetched             # импорт из локальной папки
python -m norms.pick --check-catalog --emit-yaml --out norms/PICK_CANDIDATES.md  # кандидаты + где цитаты
python -m pytest -q norms/tests          # тесты без сети, GPU и весов
```

Одна команда для L1/L2 после появления текстов (CPU, секунды, без GPU):
`python -m norms.fetch --git-ref origin/data/norms-sources && python -m norms.pick --check-catalog --out norms/PICK_CANDIDATES.md && python -m norms.validate`.
На выходе: `NOT_FOUND`/`FOUND_OTHER_CLAUSE` по цитатам, кандидаты по типам, итог `validate`.
Метрик FP/FN, latency и VRAM у этого модуля нет: он не работает с видео.

Сверка человеком — по `HUMAN_CHECKLIST.md` (15–20 минут). `verified: true` и флаги `*_checked_by_human`
ставит только человек.
