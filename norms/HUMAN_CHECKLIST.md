# Чек-лист сверки норм для человека (15–20 минут)

Цель — подтвердить или отклонить нормы каталога по официальному тексту. Агент A13 не имел доступа
к adilet.zan.kz, поэтому все цитаты сейчас взяты из поисковой выдачи (`verified: false`).
Всё ниже работает на CPU без GPU и сети (кроме шага 1Б и браузера).

## 0. Подготовка (1 мин)

```bash
pip install "PyYAML>=6,<7" pytest      # если ещё нет
python -m norms.validate               # должно быть: OK
```

## 1. Полные тексты (3 мин) — один из вариантов

- **А. L1 уже запушил ветку `data/norms-sources` (папка `norms_fetched/`):**
  ```bash
  git fetch origin data/norms-sources
  python -m norms.fetch --git-ref origin/data/norms-sources   # импорт в norms/sources/*.md без checkout
  ```
- **Б. Есть интернет:** `python -m norms.fetch` (скачает обе страницы adilet).
- **В. Файлы лежат локально:** `python -m norms.fetch --from-dir norms_fetched`.

Проверить: в шапке обоих файлов `norms/sources/*.md` стоит `retrieval: fulltext`.

## 2. Где в полном тексте стоят цитаты каталога (2 мин)

```bash
python -m norms.pick --check-catalog --emit-yaml --out norms/PICK_CANDIDATES.md
python -m norms.validate
```

В разделе «Цитаты каталога в полном тексте» отчёта `PICK_CANDIDATES.md`:
- `FOUND` — цитата стоит в указанном пункте;
- `FOUND_OTHER_CLAUSE` — цитата есть, но в другом пункте: исправить `clause` в `catalog.yaml`;
- `NOT_FOUND` — цитаты в полном тексте нет: заменить её дословным текстом найденного пункта или удалить норму.
  `validate` в этом случае тоже упадёт — так и должно быть.

## 3. Цитата и редакция по официальной странице (5 мин)

Открыть в браузере https://adilet.zan.kz/rus/docs/V1900019680 и https://adilet.zan.kz/rus/docs/V2000020075.

- [ ] Статус «Действующий», дата последней редакции. Записать в `documents.<id>.in_force` и
      поставить `revision_checked: true`.
- [ ] Для каждой нормы найти пункт и сверить цитату слово в слово. Отдельно проверить написание п. 12:
      поиск вернул и «ценостей» (Ф10), и «ценностей» (Ф10б). Оставить то, что на adilet.
- [ ] Если совпало: в `rule_checks[i]` поставить `quote_checked_by_human: true`, в норме —
      `verified: true`. Валидатор не даст этого сделать без полного текста.

## 4. Применимость к поведению (5 мин) — отдельно от цитаты

Для каждого `candidate`-типа прочитать пункт целиком и условия из `rule_checks[i].applicability`:

- [ ] **V02 (п. 22 НБРК № 231):** пункт про уход до окончания обслуживания клиента. Применим, только если
      клиент был у окна и операция не завершена. Фраза о рабочем месте (наличные клиента на столе, ранее
      принятые — в специальных устройствах): установить номер пункта и перечень устройств; требуется ли
      их запирать.
- [ ] **V08 (п. 20 НБРК № 231):** пункт про приём наличных от клиента. Пересчёт без клиента у окна
      подпадает? Внутренний пересчёт — нет. Присутствие клиента — по роли посетителя у окна, не по внешности.
- [ ] **V09 (п. 12 НБРК № 231):** личные вещи хранятся вне кассового узла. Является ли касса на видео
      частью кассового узла (а не операционной кассой вне кассового узла)? Если нет, норма не применима.
- [ ] Если применимо: `applicability_checked_by_human: true`. Если все нормы типа `verified` и применимы,
      ставить `legal_status: confirmed`. Если не применимо: убрать норму и поставить `legal_status: disabled`.
- [ ] Не натягивать: телефон, еда, открытая дверь, второй человек в кадре сами по себе не нарушение;
      допуск и личность по видео не устанавливаются.

## 5. Типы без пункта (3 мин)

В `PICK_CANDIDATES.md` просмотреть разделы V01–V07:
- [ ] V01, V03, V04, V07: пункты о доступе в кассовый узел, хранении ценностей и запирании сейфа в течение дня,
      приёме сумок (номер пункта для «3) проверяет целостность сумки…»). Найденный пункт переносить
      YAML-заготовкой в `rules` (`verified: false`), добавить `rule_checks`, поставить `legal_status: candidate`.
- [ ] Ничего прямого не нашли — тип остаётся «без пункта, без правового вывода». Это допустимо.

## 6. Зафиксировать (1 мин)

```bash
python -m norms.validate --write-fallback --write-matrix
python -m norms.validate && python -m pytest -q norms/tests
git add norms/ && git commit -m "[A13] norms: сверка с adilet (<кто>, <дата>)"
```

В `rule_checks[i]` можно добавить `checked_by: "<инициалы>"` и `checked_on: "<YYYY-MM-DD>"`.
`REVIEW_MATRIX.md` после этого показывает итоговые статусы по каждому типу.
